# UI仕様書（画面別機能一覧）

`sec-10q-qa-rag-overview.md` の主要機能（§3）と `architect.md` のバックエンド実装（Query API Worker）を元に、UIデザイン（claude design 等への依頼）のための画面別仕様を定義する。

## 0. 前提

- **対象**：デスクトップ向け（最小幅はおおよそ 1024px を想定）。モバイル対応は本仕様の範囲外
- **免責表示**：投資助言ではないことを画面に明示する（概要書 §7）。全画面の共通要素として、ヘッダーまたはフッターに固定表示する
- **バックエンド**：既存の Cloudflare Workers API（`/api/ask`, `/api/eval/run`, `/api/eval/run-generation`）を呼び出す。API契約は §3 を参照
- **対象書類**：初期版は 10-Q のみ（企業は Amazon.com, Inc. の1社・1四半期分のサンプルデータのみ投入済み）。UI上の企業・四半期フィルタは将来の複数企業・複数四半期対応を見据えた項目として用意するが、現状は選択肢が1つしかない状態で動作する

## 1. 画面構成

| # | 画面名 | 役割 |
|---|---|---|
| 1 | 質問応答画面 | 自然言語で質問し、根拠付きの回答・拒否理由を確認する（メイン画面） |
| 2 | 評価結果画面 | ゴールデンセットに対する自動評価の指標・問題ごとの結果を確認する |

## 2. 画面1：質問応答画面

### 2.1 目的

ユーザーが10-Qの内容について自然言語で質問し、引用付きの回答、または拒否理由を受け取る。概要書 §3「主な機能」の「質問応答」「引用表示」「拒否動作」「年度・企業の絞り込み」「根拠の確認」に対応する。

### 2.2 レイアウト構成要素

#### (a) ヘッダー
- アプリ名・ロゴ（任意）
- 免責文言：「本サービスは投資助言を目的としたものではありません。表示される内容は SEC への提出書類に基づく情報の抜粋であり、正確性・完全性を保証するものではありません。」のような文言を常時表示（バナー形式、閉じられない）

#### (b) 絞り込みパネル
質問を送る前に検索対象を絞り込むための入力群。`/api/ask` の `filter` パラメータに対応。

| 項目 | UI要素 | 対応フィールド | 備考 |
|---|---|---|---|
| 企業ティッカー | セレクトボックス（単一選択） | `filter.ticker` | 初期値は投入済みデータの先頭（例：AMZN）。未選択時はフィルタなしで全件検索 |
| 書類種別 | セレクトボックス（単一選択） | `filter.formType` | 選択肢は `10-Q`（将来 `10-K` 追加）。初期版は `10-Q` 固定表示でよい |
| 会計年度 | セレクトボックス（単一選択） | `filter.fiscalYear` | 投入済みデータの年度一覧から動的に選択肢を生成することを想定するが、初期版は固定値でよい |
| 四半期 | セレクトボックス（単一選択） | `filter.fiscalQuarter` | 選択肢は `Q1`/`Q2`/`Q3`。10-K選択時は非表示またはグレーアウト |
| 絞り込みクリア | ボタン（テキストリンク程度の見た目で可） | - | 全フィルタを未選択状態に戻す |

**挙動**：絞り込みは質問入力欄の送信時に一緒に送られる。絞り込みを一切設定しない場合、`filter` は送らない（全件検索）。

#### (c) 質問入力欄
- 複数行対応のテキスト入力（テキストエリア）
- 送信ボタン（Enterキーでの送信は改行と競合するため、Ctrl+Enter または明示的なボタンクリックで送信）
- 送信中はボタンを無効化し、ローディング状態を表示（生成は数秒〜十数秒かかる想定）
- プレースホルダー例：「Amazonの2026年第2四半期の売上高はいくらですか？」

#### (d) 回答表示エリア
質問送信後、`/api/ask` のレスポンスに基づいて以下のいずれかを表示する。

**ケースA：回答できた場合**（レスポンスの `refused: false`）

| 要素 | 対応フィールド | 表示内容 |
|---|---|---|
| 回答本文 | `answer` | 強調表示（見出しや太字で目立たせる） |
| 引用リスト | `citations`（配列：各要素 `chunkId`, `quote`） | 回答の下に「根拠」として列挙。各引用について以下を表示 |
| ├ 引用文 | `citations[].quote` | 引用符や区切り線で本文と視覚的に区別 |
| └ 引用元セクション | `retrieved` 配列を `chunkId` で突き合わせて `item` を表示 | 例：「Segment Information (Tables)」。`retrieved[].chunkId`・`retrieved[].item` を参照 |
| SEC原本へのリンク | 現状APIレスポンスに含まれない（`filing_url` は未接続。§4「既知の制約」参照） | 将来実装：引用元の書類URLへの外部リンクアイコン |

**ケースB：拒否した場合**（レスポンスの `refused: true`）

| 要素 | 対応フィールド | 表示内容 |
|---|---|---|
| 拒否理由 | `refusalReason` | 「該当する記載が見つかりませんでした」等の文言を、回答とは視覚的に区別した形式（警告色・アイコン等）で表示。断定的な正答ではないことが一目で分かるデザインにする |

**共通：参考情報（任意で開閉できる補助表示）**
- 検索でヒットしたチャンクの一覧（`retrieved` 配列：`chunkId`, `item`, `score`）を、折り畳み（アコーディオン）で表示できるようにする。デバッグ・透明性確認用途であり、デフォルトは非表示
- 本セクションは「どのセクションを参照したか」を示す、通常のエンドユーザー向けには補助的な情報という位置づけ

#### (e) 質問履行エラー表示
- API呼び出し自体が失敗した場合（ネットワークエラー、400/500エラー等）のエラーメッセージ表示
- 拒否（`refused: true`）とは別のUI（システムエラーであることが分かる表現）にする

### 2.3 画面状態

| 状態 | 説明 |
|---|---|
| 初期状態 | 質問入力欄が空、回答表示エリアは「質問を入力してください」のようなガイダンス表示 |
| 送信中（ローディング） | 送信ボタン無効化、スピナー等の進行中インジケータを回答表示エリアに表示 |
| 回答表示（成功） | 2.2(d) ケースA |
| 回答表示（拒否） | 2.2(d) ケースB |
| エラー表示 | 2.2(e) |

### 2.4 やり取りの履歴について

初期版では単発の質問応答（直前の1問のみ表示）を基本とする。複数の質問と回答を時系列で並べるチャット形式の履行表示は、要件として明示されていないため本仕様では対象外とするが、デザイン上「後から履行表示（チャット形式）に拡張しやすいレイアウト」を意識してもらえると望ましい。

## 3. 画面2：評価結果画面

### 3.1 目的

ゴールデンセット（`evals/golden_set.jsonl`、16問）に対する自動評価の結果を確認する。概要書 §10「README：評価結果表」に相当する内容を、UI上でも確認できるようにする。想定利用者は開発者自身または技術的な評価者であり、エンドユーザー（投資リサーチを行う個人等）向けではない。

### 3.2 レイアウト構成要素

#### (a) 評価実行コントロール
| 要素 | 対応API | 備考 |
|---|---|---|
| 「検索評価を実行」ボタン | `POST /api/eval/run` | 実行後、画面下部に結果が反映される。数秒〜数十秒かかる |
| 「生成・拒否評価を実行」ボタン | `POST /api/eval/run-generation` | LLM呼び出しを伴うため検索評価より時間がかかる（実測で1分程度）。実行中は明確なローディング表示が必要 |

#### (b) 指標サマリーカード
直近の評価結果を指標ごとにカード形式で表示する。

**検索評価（`/api/eval/run` のレスポンス、または `eval_runs` テーブルの `config.kind = "retrieval"` の最新行）**

| 指標 | フィールド | 表示例 |
|---|---|---|
| Recall@k | `recallAtK` | 0.80（パーセンテージ表示でも可：80%） |
| MRR | `mrr` | 0.675 |
| 評価対象問題数 | `evaluatedQuestions` / `totalQuestions` | 10 / 16（citationを持つ問題のみが評価対象） |

**生成・拒否評価（`/api/eval/run-generation` のレスポンス、または `config.kind = "generation"` の最新行）**

| 指標 | フィールド | 表示例 |
|---|---|---|
| 拒否判定の正解率 | `refusalAccuracy` | 0.8125 |
| 誤って拒否した割合 | `falseRefusalRate` | 0.30（回答可能な質問を誤って拒否） |
| 拒否すべきなのに回答してしまった割合 | `missedRefusalRate` | 0.00 |
| 評価対象問題数 | `totalQuestions` | 16 |

この2種類の指標は別々のタイミングで実行されるため、画面上は「検索評価」セクションと「生成・拒否評価」セクションを分けて配置する。

#### (c) 問題ごとの結果テーブル

指標サマリーの下に、各ゴールデンセット問題の結果を一覧表示する。

**検索評価の結果テーブル**（`results` 配列、各要素 `id`, `questionType`, `hit`, `rank`, `topChunkIds`）

| 列 | 内容 |
|---|---|
| 問題ID | `id`（例：gs-001） |
| 質問タイプ | `questionType`（simple_fact / table_reading / unanswerable / period_comparison / ambiguous / prompt_injection） |
| ヒット有無 | `hit`（true/false/null）。null は「citationが無い＝検索評価の対象外」であることを明示する表示にする |
| 正解チャンクの順位 | `rank`（1始まり、null は見つからなかったことを示す） |

**生成・拒否評価の結果テーブル**（`results` 配列、各要素 `id`, `questionType`, `expectedRefusal`, `actualRefusal`, `correct`, `answer`, `refusalReason`）

| 列 | 内容 |
|---|---|
| 問題ID | `id` |
| 質問タイプ | `questionType` |
| 期待される挙動 | `expectedRefusal`（true＝拒否すべき、false＝回答すべき） |
| 実際の挙動 | `actualRefusal` |
| 正誤 | `correct`（期待と実際が一致したか）。一致・不一致が視覚的に一目で分かる表示（○×、色分け等）が望ましい |
| 回答内容または拒否理由 | `answer` または `refusalReason` |

質問文そのもの（`question`）や期待される正解（`answer` フィールド、ゴールデンセット側）は現状APIレスポンスに含まれていないため、問題IDのみでの一覧表示になる（詳細をクリックして質問文を見る、といった機能は将来拡張）。

#### (d) 実行履行（任意）
`eval_runs` テーブルには実行履行が蓄積されるが、現状「最新の結果を返す」専用のAPIはなく、`/api/eval/run` 系のエンドポイントは呼び出した瞬間に新規実行してその結果を返す仕様になっている。そのため本画面は「ボタンを押すとその場で再評価が走り、結果が表示される」という単純な作りを基本とし、過去の実行履行をグラフ化する等の機能は本仕様の範囲外とする。

### 3.3 画面状態

| 状態 | 説明 |
|---|---|
| 初期状態 | まだ評価を実行していない状態。「評価を実行してください」のガイダンス表示 |
| 実行中 | 対応するボタンを無効化し、ローディング表示 |
| 結果表示 | 3.2(b)(c) |
| エラー表示 | API呼び出し失敗時のエラーメッセージ |

## 4. 既知の制約（デザイン時の留意点）

- **`filing_url`（SEC原本へのリンク）は未接続**：ゴールデンセットのメタデータ上は `filing_url` フィールドが定義されているが、現状 `"PLACEHOLDER"` という値が入っており、実際のSEC EDGAR URLではない（`docs_jp/issues.md` 参照）。デザイン上は「外部リンクアイコン」の表示位置は確保しておき、実装時に有効化する想定でよい
- **質問は日本語、文書（引用文）は英語**：チャンク本体はSEC 10-Qの英語原文であるため、引用文（`quote`）は英語表示になる。回答本文（`answer`）もLLMが生成する言語は質問の言語に従う想定だが、引用文は原文のまま英語になる点を考慮したレイアウトにする（英語の長いテーブル形式テキストが引用文として表示されることがある）
- **拒否理由が英語になることがある**：生成モデルの応答言語が安定しておらず、`refusalReason` が日本語・英語どちらで返ってくるか現状保証されていない（`docs_jp/issues.md` §9参照）。デザイン上はどちらの言語でも崩れない表示にする
- **回答生成には数秒〜十数秒、評価実行（特に生成・拒否評価）には1分程度かかる**：ローディング状態のデザインを軽視しないこと
- **企業・四半期フィルタの選択肢は現状1つしかない**：複数企業・複数四半期のデータが投入されるまでは、フィルタUIが機能していないように見える可能性がある。モックデータの前提（1企業・1四半期のみ）を踏まえたデザインにする
